城市网约车平台 · 使用教程

一个基于 MySQL + Java 前后端的网约车模拟系统：乘客下单、平台派单、司机接单执行行程， 系统按里程与时长自动计费，每一步状态都会留痕。按角色登录后即可在“工作台”里操作。

  • –注册乘客
  • –签约司机
  • –累计订单
  • –累计营收(元)
  • –在线司机
  • –完成订单

① 四步上手

  1. 1
    选择身份登录

    乘客用手机号、司机用手机号、管理员用 admin 登录，演示账号见右侧。

  2. 2
    乘客叫车

    在乘客端选择上车地点与目的地，点“立即叫车”，订单进入平台派单池（待派单）。

  3. 3
    司机接单并执行

    司机上线后在派单池接单，依次点“已到达”“开始行程”，到达目的地后“完成计费”。

  4. 4
    自动结算与评价

    系统按当前计价规则算出车费并累加司机业绩；乘客可在“我的行程”里评价本次服务。

③ 订单状态流转

待派单 WAIT → 已接单 ACCEPT → 已到达 ARRIVE → 行程中 ONTRIP → 已完成 DONE

任何未开始的环节都可以取消（变为 CANCEL）；状态只能按箭头方向流转，数据库触发器会拒绝倒流与非法 跳转，“已完成 / 已取消”的订单不能再改状态。

接单条件司机在线 + 车辆运营 + 该司机没有进行中的订单，三条同时满足才能接单
状态留痕每次状态变化都写入 order_status_log，记录操作者（乘客/司机/系统）与时间
并发安全接单用事务 + 行锁（FOR UPDATE），两个司机同时点接单也只会有一个成功

④ 计价规则

车费 = 起步价 ＋ max(里程 − 包含里程, 0) × 每公里单价 ＋ 时长 × 每分钟单价 （不低于最低消费）

规则起步价含公里元/公里元/分钟最低消费
加载中…

订单完成时会把当时生效的规则快照写进订单，之后调整规则不会改变历史账单。

⑤ 常见问题

为什么司机接不了单？

依次检查：司机是否已“上线接单”、名下车辆是否为“运营”状态、该司机是否还有 已接单/已到达/行程中 的订单。

完成行程时提示“必须给出里程与时长”？

计费需要里程（公里）与时长（分钟）两个输入，请先在“我的行程”上方填写，再点“完成计费”。

为什么车费和我按里程估的不一样？

车费包含时长费与起步价，并且有最低消费；具体公式见左侧“计价规则”，实际取当前生效的那一条规则。

订单为什么不能取消了？

只有待派单、已接单、已到达的订单可以取消；行程中、已完成、已取消的订单不能再改。

换个账号演示数据会乱吗？

不会。乘客只能看到自己的订单，司机只能看到派单池与自己的行程，管理员看到全部，数据范围由视图与账号权限控制。

按钮上的气泡怎么出来的？

鼠标在按钮上停留约 0.1 秒即弹出；键盘 Tab 聚焦也会显示，空间不足时气泡自动翻到按钮下方。
